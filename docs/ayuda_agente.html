🖥️ DLSlab — Agente del Estudiante

Guía de instalación y administración · Versión 1.0

¿Qué es el Agente DLSlab?

El Agente DLSlab (DLSlab_Agent.exe) es el componente que se instala en cada PC del laboratorio (estudiantes). Se conecta automáticamente al servidor del profesor (DLSlab_Server.exe) y permite la supervisión y gestión remota del equipo.

El agente está diseñado para ser transparente para el estudiante: no aparece como ventana en la barra de tareas, solo como un pequeño ícono en la bandeja del sistema (área de notificaciones).

ℹ️ Destinatarios de esta guía
Esta guía está dirigida a administradores de TI o al técnico del laboratorio responsable de instalar y mantener el agente en los equipos de los estudiantes.
Requisito Detalle
Sistema Operativo Windows 10 / 11 (64-bit)
Privilegios Administrador local (para políticas web y tarea programada)
Red Misma LAN que el PC del profesor (puerto TCP 9000 abierto)
Sin Internet No requiere conexión a Internet para operar

Instalación rápida

  1. Copia DLSlab_Agent_Setup_v1.0.exe al equipo del estudiante.
  2. Ejecuta el instalador como Administrador.
  3. Cuando el asistente pregunte la dirección del servidor, ingresa la IP o nombre del PC del profesor (ej. 192.168.1.100 o DLSLAB-PROF).
  4. Completa la instalación. El agente se iniciará automáticamente y quedará configurado para arrancar en cada inicio de sesión.
  5. El ícono de DLSlab aparecerá en la bandeja del sistema.
💡 Consejo
Si no sabes la IP del PC del profesor, en ese equipo abre una ventana de comandos y escribe ipconfig. Busca la dirección IPv4 de la interfaz de red local.

Usando el instalador (recomendado)

El instalador DLSlab_Agent_Setup_v1.0.exe automatiza todo el proceso:

  1. Copia DLSlab_Agent.exe a %ProgramFiles%\DLSlab\.
  2. Solicita la dirección del servidor y crea %ProgramData%\DLSlab\config.ini automáticamente.
  3. Registra una Tarea Programada en el Programador de tareas de Windows que inicia el agente automáticamente al iniciar sesión cualquier usuario.

Parámetros del instalador

Campo en el instalador Descripción Ejemplo
Servidor DLSlab IP o nombre de host del PC del profesor 192.168.1.100 o DLSLAB-PROF

Desinstalación

Ve a Panel de Control → Programas → Desinstalar un programa y selecciona DLSlab Agent. La desinstalación elimina automáticamente:

  • El archivo config.ini y el directorio de datos.
  • La Tarea Programada de inicio automático.
  • Los archivos instalados.
⚠️ Requiere Administrador
Tanto la instalación como la desinstalación deben ejecutarse con permisos de Administrador.

Instalación manual (avanzado)

Si prefieres instalar sin el asistente, sigue estos pasos:

  1. Copia DLSlab_Agent.exe al directorio deseado, por ejemplo: 
    C:\Program Files\DLSlab\DLSlab_Agent.exe
  2. Crea el archivo de configuración C:\ProgramData\DLSlab\config.ini: 
    ; DLSlab Agent — configuración
[server]
host = 192.168.1.100
port = 9000
  3. Ejecuta el agente manualmente (como Administrador): 
    DLSlab_Agent.exe
    O con parámetros de línea de comandos (sobreescriben el config.ini): 
    DLSlab_Agent.exe --server-ip 192.168.1.100 --server-port 9000

Parámetros de línea de comandos

Parámetro Por defecto Descripción
--server-ip 127.0.0.1 IP o hostname del servidor (PC del profesor)
--server-port 9000 Puerto TCP del servidor
--client-id Auto (hostname + ID) Identificador manual del cliente

Configurar inicio automático manual

Para que el agente arranque automáticamente sin el instalador, crea una tarea en el Programador de tareas de Windows:

  1. Abre el Programador de tareas (taskschd.msc) como Administrador.
  2. Crea una tarea básica: Nombre: DLSlab Agent.
  3. Desencadenador: Al iniciar sesión (cualquier usuario).
  4. Acción: Iniciar programa → ruta de DLSlab_Agent.exe.
  5. En las propiedades de la tarea, pestaña General: marca "Ejecutar con los privilegios más altos".

Despliegue masivo en el laboratorio

Para instalar el agente en múltiples equipos simultáneamente desde el servidor:

Opción 1: Script PowerShell (red compartida)

$computers = @("PC-LAB-01", "PC-LAB-02", "PC-LAB-03")
foreach ($pc in $computers) {
    # Copiar ejecutable
    Copy-Item "DLSlab_Agent.exe" "\\$pc\C$\Program Files\DLSlab\"
    # Crear config.ini
    $config = "[server]`nhost = 192.168.1.100`nport = 9000"
    New-Item -Path "\\$pc\C$\ProgramData\DLSlab\" -ItemType Directory -Force
    Set-Content "\\$pc\C$\ProgramData\DLSlab\config.ini" $config
}

Opción 2: Ejecutar el instalador silenciosamente

El instalador de Inno Setup admite instalación desatendida:

DLSlab_Agent_Setup_v1.0.exe /SILENT /SP-
ℹ️ Nota sobre instalación silenciosa
En modo silencioso, el instalador usa el valor por defecto para el servidor (DLSLAB-PROF). Modifica previamente el script setup_agent.iss o edita el config.ini tras la instalación.

Archivo de configuración

El agente lee su configuración desde: C:\ProgramData\DLSlab\config.ini 

; DLSlab Agent — configuración generada por el instalador
[server]
host = 192.168.1.100
port = 9000
Clave Descripción Ejemplo
host IP o hostname del PC del profesor 192.168.1.100
port Puerto TCP del servidor 9000
💡 Cambiar el servidor
Si la IP del profesor cambia, edita este archivo con Notepad (como Administrador) y reinicia el equipo o la tarea programada del agente.

Qué hace el Agente

El agente opera completamente en segundo plano. Sus funciones principales son:

📸

Captura de pantalla

Envía una miniatura comprimida (320×180 px) al servidor cada 2 segundos.

🔒

Bloqueo de pantalla

Muestra una superposición negra con mensaje cuando el profesor bloquea el equipo.

📡

Recepción de transmisión

Muestra la pantalla del profesor o de un compañero cuando se activa la transmisión.

🖱️

Control remoto

Ejecuta eventos de teclado y ratón enviados por el profesor.

🛡️

Políticas de apps

Cierra automáticamente aplicaciones prohibidas según la política activa.

🌐

Políticas web

Bloquea dominios modificando el archivo hosts del sistema.

⚡

Control de energía

Ejecuta comandos de apagado, reinicio, bloqueo y cierre de sesión.

📁

Recepción de archivos

Guarda en el Escritorio los documentos enviados por el profesor.

📋

Reporte de violaciones

Notifica al servidor cuando un estudiante intenta abrir una app o web bloqueada.

🔄

Reconexión automática

Si pierde la conexión, reintenta reconectarse automáticamente.

Ícono en la bandeja del sistema

El agente aparece como un ícono en la bandeja del sistema (esquina inferior derecha de la pantalla del estudiante). Al hacer clic derecho sobre él, se muestra un menú con la opción de salir del agente.

ℹ️ Visibilidad para el estudiante
El ícono indica al estudiante que el laboratorio está siendo supervisado. Se recomienda informar a los alumnos sobre el sistema de monitoreo al inicio del curso, conforme a las normativas de privacidad institucionales.
Estado del ícono Significado
Ícono normal Agente activo y conectado al servidor.
Ícono atenuado / sin señal Agente activo pero sin conexión al servidor (intentando reconectar).

Comandos que puede recibir el Agente

El agente responde a los siguientes comandos enviados desde la consola del profesor:

Comando Efecto en el equipo del estudiante
Bloquear pantalla Muestra una superposición negra con el mensaje configurado.
Desbloquear pantalla Elimina la superposición y restaura la pantalla.
Transmitir pantalla del profesor Abre una ventana que muestra la pantalla del docente en tiempo real.
Presentar pantalla de alumno Muestra la pantalla de un compañero en una ventana.
Control remoto Acepta y ejecuta eventos de teclado/ratón del profesor.
Apagar Inicia el apagado del equipo tras el delay indicado.
Reiniciar Inicia el reinicio del equipo tras el delay indicado.
Bloquear estación Ejecuta el bloqueo de pantalla del SO Windows.
Cerrar sesión Cierra la sesión del usuario activo.
Abrir URL Abre la URL indicada en el navegador predeterminado.
Ejecutar app Lanza el ejecutable indicado con los argumentos especificados.
Enviar archivo Guarda el documento recibido en el Escritorio del usuario.

Políticas de aplicaciones y web

Política de aplicaciones

Cuando el profesor activa una política de aplicaciones, el agente monitorea continuamente los procesos en ejecución.

Modo Comportamiento del agente
Sin restricciones No monitorea ni cierra aplicaciones.
Lista Blanca Cierra cualquier proceso que no esté en la lista permitida.
Lista Negra Cierra cualquier proceso que sí esté en la lista prohibida.

Cuando el agente cierra un proceso, reporta la violación al servidor (visible en el log de políticas de la consola del profesor).

Política web

El agente modifica el archivo hosts del sistema para bloquear dominios.

Modo Comportamiento del agente
Sin restricciones El archivo hosts no se modifica.
Bloquear todo Redirige todos los dominios a 0.0.0.0 en el archivo hosts.
Lista blanca de URLs Bloquea todos los dominios excepto los de la lista permitida.

El agente crea un backup automático del archivo hosts en C:\Windows\System32\drivers\etc\hosts.dlslab.bak antes de aplicar cualquier cambio, y lo restaura al limpiar la política.

⚠️ Requiere Administrador
La modificación del archivo hosts requiere que el agente se ejecute con permisos de Administrador. Si la política web no funciona, verifica el nivel de ejecución de la tarea programada.

Wake-on-LAN

El agente reporta la dirección MAC de la tarjeta de red al servidor al conectarse. Esta información se almacena en el servidor para poder enviar paquetes WoL cuando el equipo esté apagado.

Habilitar WoL en los equipos del laboratorio

  1. En la BIOS/UEFI: Busca la opción Wake on LAN, Power On By PCI-E o similar y actívala.
  2. En Windows: Abre el Administrador de dispositivos → Adaptadores de red → doble clic en la NIC → pestaña Administración de energía → marca "Permitir que este dispositivo active el equipo".
  3. El equipo debe haberse conectado al menos una vez al servidor para registrar su MAC.
ℹ️ Limitaciones de WoL
  • Generalmente solo funciona en redes cableadas.
  • El router/switch debe estar en el mismo segmento de red (no funciona entre VLANs sin configuración especial).
  • Algunos equipos pierden la configuración WoL tras actualizaciones de drivers.

Procedimientos paso a paso

▶ Actualizar la dirección del servidor

  1. Abre el Bloc de notas como Administrador.
  2. Abre el archivo C:\ProgramData\DLSlab\config.ini.
  3. Cambia el valor de host a la nueva IP del profesor.
  4. Guarda el archivo.
  5. Reinicia el equipo o la tarea programada del agente.

▶ Reiniciar el Agente manualmente

  1. Abre el Programador de tareas (taskschd.msc).
  2. Busca la tarea DLSlab Agent.
  3. Haz clic derecho → Ejecutar.

▶ Verificar que el Agente está corriendo

  1. Busca el ícono de DLSlab en la bandeja del sistema.
  2. Alternativamente, abre el Administrador de tareas (Ctrl+Shift+Esc) y busca DLSlab_Agent.exe en la lista de procesos.

▶ Probar conectividad con el servidor

# Desde el equipo del estudiante, verificar que el servidor responde:
Test-NetConnection -ComputerName 192.168.1.100 -Port 9000

Si el resultado muestra TcpTestSucceeded : True, la conexión es posible.

Preguntas frecuentes

¿El Agente afecta el rendimiento del equipo?

El impacto es mínimo. Las capturas de pantalla se comprimen a baja resolución (320×180 px, calidad JPEG 40%) y se envían cada 2 segundos. El uso de CPU y memoria es muy bajo en condiciones normales.

¿Los estudiantes pueden cerrar el Agente?

El Agente se ejecuta con privilegios de administrador. Un estudiante con cuenta estándar no puede cerrarlo ni eliminarlo. Solo un usuario administrador puede detenerlo desde la bandeja del sistema o el Administrador de tareas.

¿Qué pasa si el equipo pierde la conexión con el servidor?

El agente detecta la desconexión y reintenta la conexión automáticamente usando espera exponencial (comienza en pocos segundos y va aumentando el intervalo hasta reconectarse). No requiere intervención manual.

¿Las políticas web siguen activas si el servidor se cae?

Sí. Una vez aplicada la política web (modificación del archivo hosts), permanece activa aunque el agente pierda la conexión. El profesor debe enviar el comando "Limpiar políticas" para restaurar el archivo hosts original.

¿El agente funciona con usuarios estándar (no administradores)?

El agente se ejecuta correctamente con usuarios estándar para la mayoría de funciones (miniaturas, bloqueo de pantalla, transmisión). Sin embargo, las políticas web requieren permisos de administrador. Se recomienda configurar la tarea programada con nivel de ejecución elevado.

¿Cómo sé que el agente está conectado al servidor?

Si el agente está conectado, la miniatura del equipo aparece activa (punto verde) en la consola del profesor. También puedes usar el Programador de tareas para ver el estado de la tarea DLSlab Agent.

¿Puedo instalar el agente en equipos fuera del laboratorio (WiFi)?

Sí, mientras el equipo esté en la misma red local que el servidor y pueda alcanzar el puerto 9000. Wake-on-LAN no funcionará en WiFi, pero el resto de funciones sí.

Solución de problemas

El agente no aparece en la consola del profesor

  • Verifica que DLSlab_Agent.exe está en ejecución (Administrador de tareas).
  • Comprueba que config.ini tiene la IP correcta del servidor.
  • Ejecuta en PowerShell: Test-NetConnection -ComputerName [IP_PROFESOR] -Port 9000
  • Verifica que el Firewall del PC del profesor permite el puerto 9000 TCP.

Las políticas web no se aplican

  • Confirma que el agente tiene permisos de Administrador en la tarea programada.
  • Verifica que el archivo hosts puede ser modificado: C:\Windows\System32\drivers\etc\hosts
  • Algunos navegadores con DoH (DNS over HTTPS) ignoran el archivo hosts. Desactiva DoH en el navegador o usa políticas de grupo para bloquearlo.

El agente no arranca automáticamente al iniciar sesión

  • Abre el Programador de tareas y verifica que la tarea DLSlab Agent existe y está habilitada.
  • Revisa el historial de la tarea para ver si hay errores de ejecución.
  • Reinstala el agente con el instalador oficial.

El agente se cierra inesperadamente

  • Revisa el Visor de eventos de Windows (eventvwr.msc) → Registros de Windows → Aplicación → busca errores de DLSlab_Agent.
  • Verifica que el antivirus no está bloqueando el ejecutable.

Restaurar el archivo hosts manualmente

Si el archivo hosts quedó bloqueado tras un fallo, restaura el backup:

# En PowerShell como Administrador:
Copy-Item "C:\Windows\System32\drivers\etc\hosts.dlslab.bak" `
          "C:\Windows\System32\drivers\etc\hosts" -Force

Cómo reportar un error

Contacta al soporte con la siguiente información:

  1. Descripción del problema y pasos para reproducirlo.
  2. Versión de DLSlab Agent (propiedades del ejecutable).
  3. Sistema operativo y versión de Windows.
  4. Contenido del config.ini (omite datos sensibles de red si aplica).

Glosario

Término Definición
Agente Programa (DLSlab_Agent.exe) que se ejecuta en el PC del estudiante y se conecta al servidor del profesor.
Servidor La Consola del Profesor (DLSlab_Server.exe) que recibe las conexiones y envía comandos.
Tarea Programada Configuración del Programador de tareas de Windows que inicia el agente automáticamente al iniciar sesión.
config.ini Archivo de configuración del agente con la dirección del servidor.
hosts (archivo) Archivo del sistema usado para bloquear dominios web. Ruta: C:\Windows\System32\drivers\etc\hosts.
Wake-on-LAN (WoL) Tecnología que permite encender un PC apagado a través de la red local enviando un "paquete mágico" a su dirección MAC.
MAC (dirección) Identificador único de la tarjeta de red de un equipo, usado para WoL (formato: AA:BB:CC:DD:EE:FF).
Puerto 9000 Puerto TCP usado para la comunicación entre el agente y el servidor.
LAN Red de área local — la red interna del laboratorio.
Lista Blanca Conjunto de elementos explícitamente permitidos; todo lo demás se bloquea.
Lista Negra Conjunto de elementos explícitamente prohibidos; todo lo demás se permite.
DoH DNS over HTTPS — protocolo de navegadores que puede saltarse el archivo hosts. Puede requerir desactivación para políticas web.

Atajos y consejos para administradores

  • 🚀 Usa el despliegue masivo con PowerShell para instalar en todo el laboratorio en minutos.
  • 🔄 Si cambias la IP del servidor, solo edita config.ini en cada equipo en %Programdata%/dlslab/ — no hace falta reinstalar.
  • 🔒 Configura las cuentas de los estudiantes como usuarios estándar para evitar que modifiquen o detengan el agente.
  • 📋 Revisa el Programador de tareas regularmente para confirmar que la tarea DLSlab Agent sigue activa en todos los equipos.
  • 🖥️ Si usas imágenes del sistema (clonación), instala el agente después de clonar para que cada equipo tenga su propio client-id automático.
  • ⚡ Habilita WoL en BIOS y NIC antes de hacer la imagen maestra del equipo.
  • 🗂️ El backup del archivo hosts se guarda en hosts.dlslab.bak — guárdalo antes de cualquier cambio manual.
